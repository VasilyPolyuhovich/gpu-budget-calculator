Self-hosted LLM · GPU cost planner

Кошторис оренди GPU та вибір моделі

Одна сторінка під воркфлоу: on-demand pod з open-weight моделлю (Qwen3.6-27B / Coder-Next) через vLLM, ваги на persistent volume, білінг лише за години роботи. Ціни редагуються й зберігаються локально — підстав свої, поділись лінком. Дані звірено з реальними деплоями (серпень 2026).

03 Головна пастка — забути вимкнути

⚠ Always-on = ×8 бюджету

Уся економіка тримається на тому, що pod вимикається після сесії. Якщо він працює 24/7:

A100: $1.39 × 730 год ≈ $1 015 / міс  ·  H100: $1.99 × 730 ≈ $1 453 / міс

Запобіжники (з практики): запланований авто-terminate за розкладом (напр. cron/CI щовечора) — ловить навіть pod-и, підняті через веб-консоль без idle-stop · idle auto-stop за N хв бездіяльності · billing alert (~$200) · ваги на volume, тож наступний старт швидкий і нічого не втрачаєш.

05 Рекомендація та налаштування

Під одну карту для reasoning + код + tool-use виграє Qwen3.6-27B (якість). Для інтерактиву, де дратує затримка, тримай Qwen3-Coder-Next — ~2× швидший, non-thinking. Перемикання = один параметр, якщо запекти профілі в образ.

Модель
QuantTrio/Qwen3.6-27B-AWQ-6Bit (~28 ГБ) або bullpoint/Qwen3-Coder-Next-AWQ-4bit (~45 ГБ, швидший)
Сервер
vLLM: --quantization awq_marlin · --enable-auto-tool-choice --tool-call-parser qwen3_coder · --reasoning-parser qwen3 (лише thinking) · --max-model-len 131072 · --gpu-memory-utilization 0.92
Доступ
Завжди --api-key; стабільний URL через reverse-proxy (напр. Cloudflare Worker → поточний pod), щоб не переписувати per-pod
Ваги
HF_HOME=/workspace/hf на network volume ~100 ГБ — качати раз. HF Xet тягне ~45 ГБ за ~1 хв, тож повторне завантаження дешеве навіть без тому
Образ
Власний Docker (vLLM + парсери запечені) → старт = pull + run, без pip install щоразу
Економія
Авто-terminate за розкладом (cron/CI) + idle-stop · вимикай між сесіями · Community/Vast ≈ −40–50% до ціни

06 З досвіду реальних деплоїв

Час старту
~4–5 хв від контейнера до готовності: Xet качає ваги ~1 хв, решту з'їдають завантаження в VRAM + torch.compile + warmup — завантаження вже НЕ вузьке місце
#1 стаття витрат
Забутий увімкнений pod. Один запланований авто-terminate економить більше, ніж будь-який вибір GPU
Надійність
Найдешевший хост ≠ найнадійніший: low-stock інстанс може не стартувати контейнер (~5 хв втрати). Обирай надійний тир або роби retry/fallthrough на інший хост
Persistence
Pod-local диск гине при terminate → ваги качаються знову (з Xet це ~1 хв). Network volume = завантаження раз, але прив'язаний до одного датацентру (менший пул GPU)
Швидкість
6-bit dense ~47 tok/s; non-thinking MoE (Coder-Next) ~93 tok/s. «Повільно» у thinking-моделі — це reasoning перед відповіддю, не залізо

Ціни та бенчмарки — оцінки станом на серпень 2026; GPU-маркетплейси змінюють ставки щодня, а моделі виходять щотижня. Перед розгортанням звіряй live-ставку, наявність інстансів і актуальні AWQ-квенти на HF. Self-host обраний заради приватності даних і повного контролю над стеком.
